# tolk-vanity-placeholder

[English](README.md) · **Русский**

Маленький контракт TON на Tolk. Он держит выбранный («красивый») адрес, пока
на этот адрес не будет установлен ваш настоящий контракт.

Адрес в TON — это хеш исходных кода и данных контракта, и он не меняется
никогда. Чтобы получить адрес вроде `EQC…----Gold`, перебирают соль, пока хеш
не выйдет нужным. Перебирать прямо по настоящему контракту неудобно: любая
найденная соль пропадает, как только поменяется код, а данные обычно слишком
велики для быстрого перебора на GPU. Поэтому перебор идёт по этой заглушке:

- её код не меняется никогда;
- её данные — 40 байт: ваш публичный ключ ed25519 и 64-битная соль. Они
  хешируются одним блоком SHA-256;
- одно внешнее сообщение, подписанное вашим ключом, превращает её в ваш
  настоящий контракт. Адрес, баланс и джеттон-кошельки остаются.

## Как пользоваться

1. **Скомпилируйте один раз и заморозьте результат.**
   `npx @ton/tolk-js@1.4.2 -o placeholder.json vanity-placeholder.tolk`
   Хеш кода должен быть
   `b16b8b2cefaf342581684f59056ec1bd282e3428fb06327de53a4a737a60e497`
   (Tolk 1.4.2; Acton 1.2.0 даёт тот же). Храните именно этот BOC кода: хеш
   кода входит в каждый адрес, и другая сборка — это другие адреса.
2. **Найдите соль.** Параметры для перебора:
   `BUF1_LEN=42 SALT_OFF=34 SALT_LEN=8`, хеш кода и глубина кода `4`, шаблон
   данных `0050` + ваш 32-байтный публичный ключ + 8 нулевых байт. Сначала
   сверьте перебор с контрольными векторами из `PROMPT.md`. Решите, для
   какой формы ищете — `EQ…` или `UQ…`: последние четыре символа у них разные.
3. **Проверьте адрес** найденной соли своим SDK
   (`contractAddress(0, { code, data })`), а не только перебором.
4. **Пополните его** переводом **без возврата** (на форму `UQ…`). Перевод с
   возвратом на адрес, где ещё ничего не развёрнуто, вернётся обратно.
5. **Прогоните установку** в эмуляторе или песочнице: внешнее сообщение со
   StateInit заглушки и запросом `Become` с кодом и полными начальными
   данными вашего контракта, а затем — вывод средств вашим контрактом на
   получившемся состоянии. Отправляйте, только если вывод работает.
6. **Отправьте одно внешнее сообщение.** За одну транзакцию аккаунт
   разворачивается как заглушка и становится вашим контрактом.

## Безопасность, коротко

- Установить что-либо может только ваш ключ, только на этом адресе и только
  до `valid_until` запроса. Все проверки идут до принятия сообщения, так что
  отвергнутый запрос ничего не стоит.
- У заглушки нет своего вывода средств: до установки путь к деньгам — только
  ключ. Потеряете ключ — потеряете средства.
- Данные вашего контракта ставятся как есть, никакой конструктор не
  выполняется.
- Ваш контракт должен отвергать то же подписанное сообщение, если его
  повторят уже после установки (это так у любого контракта, который
  проверяет подпись в своём формате).
- Внешнее сообщение ограничено 65 535 байтами: код и данные должны
  поместиться.

Всё это с объяснениями — в `PROMPT.md`.

## Похожее

[ton-community/vanity-contract](https://github.com/ton-community/vanity-contract)
делает то же самое через адрес кошелька-владельца и внутреннее сообщение. Эта
заглушка работает по ключу, разворачивается и ставит контракт одним внешним
сообщением и держит данные в одном блоке SHA-256.
